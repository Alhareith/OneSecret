## الوثائق التاريخية

الملفات من `01-...` إلى `18-...` تسجل قرارات ومراحل صحيحة **في وقت تنفيذها**، لكنها قد تحتوي على افتراضات لم تعد صحيحة بعد إدخال Client-side Web Crypto ومسارات الملفات والصور.

كما يحتوي `docs/archive/` على نسخ مرجعية من ملفات الجذر التي استبدلت في مرحلة توحيد الحقيقة التقنية، مثل خطة V1 وREADME/Security/Contributing القديمة وسجل `todo.md` الطويل. وجودها للأرشفة فقط؛ لا تستخدمها كوصف للحالة الحالية.

أمثلة على تغيرات جوهرية حدثت لاحقًا:

- بعض الوثائق القديمة تصف AES للنصوص داخل Python؛ الحالي للنصوص الجديدة هو AES-256-GCM داخل المتصفح.
- بعض الوثائق القديمة تعتبر الملفات والصور خارج النطاق؛ الحالي يدعمهما فعليًا.
- `18-team-crypto-contracts.md` كان عقد عمل متوازي قبل الدمج، وليس وصفًا نهائيًا للحالة الحالية.
- بعض الوثائق تشير إلى أن DES/RSA لا يستخدمان قاعدة البيانات؛ المشاركة الحالية تستخدم تخزينًا مؤقتًا للحزم المشفرة.

لا نحذف هذه الوثائق لأنها مفيدة كسجل تطور، لكن لا نستخدمها منفردة للدفاع عن المعمارية الحالية.

## المعمارية الحالية في سطر واحد

```text
Text  -> Browser AES-256-GCM
File  -> Browser AES-256-GCM + RSA-OAEP/SHA-256
Image -> Backend Single DES-CBC + PKCS#7
```

## قاعدة تحديث التوثيق

أي تغيير في أحد الأمور التالية يجب أن يحدث معه تحديث توثيق في نفس PR:

- مكان تنفيذ التشفير.
- الخوارزمية أو mode أو key/nonce/IV size.
- ما يرسله Browser إلى Backend.
- ما تخزنه قاعدة البيانات.
- مكان وجود مفتاح فك التشفير.
- معنى one-time/expiry/cancel.
- Trust Boundary أو الضمانات الأمنية.
