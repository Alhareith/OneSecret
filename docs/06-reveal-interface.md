# المرحلة 6: صفحة المستلم والعرض التلقائي

## قرار التجربة الحالي

تفتح صفحة المستلم رابطًا بالشكل `/s/{id}`. عند فتح رابط صالح، تستدعي الواجهة `POST /api/secrets/{id}/reveal` تلقائيًا. يعيد خادم Python النص ما دام الرابط لم ينته؛ ولا يستهلكه إلا إذا اختار المرسل الإتلاف بعد أول فتح. لا يوجد زر Reveal.

هذا قرار تجربة استخدام، وليس ادعاء حماية إضافية: الرابط نفسه هو وسيلة الوصول. إضافة زر ثانٍ لا تمنع أي شخص يملك الرابط من قراءة الرسالة، بينما العرض المباشر يجعل المسار أبسط وأوضح.

## المسار الصحيح

```text
المستلم يفتح الرابط
        ↓
React يحمّل صفحة المستلم فقط
        ↓ POST /api/secrets/{id}/reveal
Python يتحقق من الصلاحية وSecret Code ثم يفك التشفير
        ↓
تظهر الرسالة في بطاقة قراءة كبيرة
        ↓
إعادة الفتح → تظهر الرسالة حتى انتهاء المدة، إلا عند خيار الإتلاف
```

يبقى `GET /api/secrets/{id}/status` في الخادم بوصفه واجهة API قائمة، لكن صفحة المستلم الجديدة لا تطلبه؛ هذا يقلّل طلب الشبكة غير الضروري عند أول فتح.

## حالات العرض

| الحالة | ما تعرضه الصفحة | هل يعود النص؟ |
|---|---|---|
| `opening` | حالة قصيرة هادئة أثناء طلب واحد | لا |
| `revealed` | النص الذي أعاده الخادم في بطاقة كبيرة | نعم، في كل فتح قبل الانتهاء افتراضيًا |
| `code` | حقل Secret Code لكشف رسالة محمية | لا، حتى يقدم المستلم الكود الصحيح |
| رابط مستهلك أو منتهٍ أو غير موجود | «هذا الرابط غير متاح» برسالة عامة | لا |
| خطأ اتصال | رسالة عامة بلا تفاصيل داخلية | لا |

## حماية طلب العرض في React

في وضع التطوير `StrictMode` قد يعيد React تشغيل بعض آثار المكوّنات لاكتشاف الأخطاء. لذلك تستخدم الصفحة `reveal-request-cache.ts` لتعيد **Promise نفسه** إذا طُلب المعرّف نفسه أثناء الفتح. النتيجة: لا يؤدي التطوير إلى طلبين POST متوازيين يستهلك الأول منهما الرابط ويجعل الثاني يفشل.

| الاختبار | النتيجة المطلوبة |
|---|---|
| رابط صالح | يظهر النص تلقائيًا من دون زر |
| إعادة فتح رابط عادي | يظهر النص حتى انتهاء المدة |
| إعادة فتح رابط إتلاف | تظهر حالة عدم الإتاحة بعد أول كشف ناجح |
| رابط غير موجود | تظهر الحالة العامة نفسها |
| تبديل اللغة | RTL للعربية وLTR للإنجليزية |
| StrictMode | طلب Reveal واحد فقط للمرة الأولى |

## حدود الحماية

لا تمنع الصفحة تصوير الشاشة أو نسخ النص بعد عرضه، ولا تستطيع حذف النص من ذاكرة جهاز المستلم. الحماية هنا هي التشفير أثناء التخزين، ومدة الصلاحية، وSecret Code الاختياري، والإتلاف الاختياري؛ وليست تحكمًا في جهاز المستلم.

## الخلاصة التي تناقش بها المدرس

> «عند فتح الرابط، يرسل React طلب Reveal واحدًا إلى FastAPI. الخادم يتحقق من انتهاء المدة وSecret Code إن وُجد، ثم يفك AES-GCM ويرسل النص. يبقى الرابط قابلًا للعرض حتى انتهاء المدة؛ وإذا اختار المرسل الإتلاف، يستخدم الخادم تحديثًا ذريًا ليجعل أول كشف صحيح هو الأخير.»
