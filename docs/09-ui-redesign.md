# المرحلة 9: إعادة تصميم الواجهة وتجربة الاستخدام

## النطاق المعتمد

اقتصرت هذه المرحلة تاريخيًا على **الواجهة وتجربة الاستخدام والأداء المدرك**. لم يتغير حينها تشفير AES-256-GCM أو الخادم. التغيير الوظيفي آنذاك كان عرض الرسالة تلقائيًا بدل طلب نقرة إضافية على زر Reveal. راجع المرحلة 11 لسلوك الصلاحية الحالي وSecret Code والإتلاف الاختياري.

> الرابط هو وسيلة الوصول. لذلك زر Reveal لا يضيف حماية تشفيرية مستقلة؛ العرض التلقائي يبقي المسار بسيطًا، بينما تحدد مدة الصلاحية والإتلاف الاختياري سلوك الوصول الحالي.

## الهوية وتجربة الاستخدام

تستخدم الصفحتان خلفية بيضاء دافئة، مساحات هادئة، خط Tajawal موحّد، وزرًا رئيسيًا داكنًا بتدرج معدني خفيف. لا توجد واجهة Dashboard أو بطاقات تسويقية أو مؤثرات ثقيلة. يظهر `Alhareith Aldahia` كتذييل هادئ في أسفل الصفحة.

| الجزء | ما يراه المستخدم |
|---|---|
| صفحة المرسل | حقل رسالة، مدة الرابط، زر إنشاء، ثم رابط قابل للنسخ بعد النجاح فقط |
| صفحة المستلم | حالة فتح قصيرة، ثم الرسالة بخط كبير داخل بطاقة قراءة واضحة |
| رابط غير متاح | رسالة عامة قصيرة من دون سبب تقني أو بيانات حساسة |
| اللغة | العربية RTL والإنجليزية LTR مع تبديل النصوص والاتجاه سويًا |

أزيلت من واجهة المستخدم أي تفاصيل عن Token أو AES أو حالة API أو منع تصوير الشاشة. هذه حدود تقنية لا ينبغي أن تتحول إلى حمل معرفي على المستخدم، لكنها تبقى موثقة في README ووثائق المراحل.

## العرض التلقائي

عند تحميل `/s/{id}` تستدعي الواجهة مباشرة `POST /api/secrets/{id}/reveal`. إذا كان الرابط صالحًا، يعيد الخادم النص حتى الانتهاء؛ ويعود الرابط غير متاح بعد أول كشف فقط عند تفعيل الإتلاف. لا ترسل صفحة المستلم طلب `GET status` أولًا، لذا لا يوجد طلب شبكة تمهيدي غير لازم.

تحتفظ `reveal-request-cache.ts` بـPromise الكشف الجاري لكل معرّف. هذا مهم في React StrictMode: إذا أعاد React تشغيل أثر الصفحة أثناء التطوير، يستعمل الطلب نفسه بدل إرسال كشف ثانٍ. أثبت سجل خادم نسخة الاستكشاف لرسالة جديدة طلب `POST .../reveal` ناجحًا واحدًا فقط.

## تحسينات التحميل

تُحمّل صفحة Reveal تحميلًا كسولًا؛ لذلك لا تدخل شيفرتها في المسار الأول لصفحة الإنشاء. لم تضف المرحلة مكتبات واجهات أو رسوم متحركة أو أصولًا كبيرة.

| قياس البناء الأخير | النتيجة |
|---|---:|
| CSS المنتج | 17.15 kB، مضغوطًا 4.37 kB |
| JavaScript لمسار الإنشاء | 403.70 kB، مضغوطًا 120.59 kB |
| JavaScript المؤجل لصفحة Reveal | 5.84 kB، مضغوطًا 1.41 kB |
| زمن بدء نقل الصفحة محليًا | 0.013 ثانية |
| زمن طلب `/api/health` محليًا | 0.003 ثانية |

هذه الأرقام قياسات محلية لنسخة استكشاف؛ لا تمثل زمن الإنترنت أو منصة النشر، لكنها تؤكد وجود فصل فعلي لصفحة المستلم وعدم إضافة حمولة مرئية أو مكتبات جديدة إلى البداية.

## التحقق المنفذ

استُخدمت نسخة استكشاف مؤقتة بقاعدة SQLite ومفتاح اختبار منفصلين، وليست قاعدة الإنتاج أو مفتاح الإنتاج.

| التحقق | النتيجة |
|---|---|
| إنشاء رسالة إنجليزية ثم فتح رابطها | ظهرت الرسالة تلقائيًا في بطاقة كبيرة بلا زر Reveal |
| إعادة فتح الرابط نفسه | ظهرت حالة عدم الإتاحة ولم يعد النص |
| رابط غير موجود | ظهرت الحالة العامة نفسها بلا تفاصيل تقنية |
| العربية والإنجليزية | تأكد RTL وLTR في صفحة الإرسال وصفحة عدم الإتاحة |
| رسالة فارغة | ظهر تنبيه قصير محليًا من دون إنشاء رابط |
| إزالة التنبيه عند الكتابة | أصلحت الصفحة بقاء التنبيه؛ يختفي فور إدخال نص غير فارغ |
| نسخ الرابط | ظهر تأكيد «تم نسخ الرابط» بعد النجاح |
| الهاتف وسطح المكتب | عاينت البطاقة والحقول والمسافة على 390×844 وسطح المكتب؛ لا تجاوز أفقي |
| وحدة تحكم المتصفح | لم يظهر أي تحذير أو خطأ في مسارات التحقق المذكورة |
| `pnpm test` | 3 ملفات اختبار و3 اختبارات ناجحة، منها اختبار مخزن الكشف |
| `pnpm check` و`pnpm build` | ناجحان؛ وظهر ملف Reveal المنفصل في مخرجات Vite |
| `pytest -q` | 60 اختبار Python ناجحًا؛ تحذير خارجي واحد من FastAPI/TestClient فقط |

## العيوب المكتشفة وإصلاحها

| العيب | المعالجة |
|---|---|
| استيراد مكرر لـ`CreateSecretPage` أوقف البناء | أزيل الاستيراد المكرر، ثم نجح فحص TypeScript والبناء |
| StrictMode قد يرسل كشفًا ثانيًا | أضيف مخزن Promise لمعرّف الرابط، مع اختبار Vitest وسجل خادم يثبت الطلب الأول المفرد |
| تنبيه الرسالة الفارغة كان يبقى بعد بدء الكتابة | أصبح معالج الحقل يمسح التنبيه عند وجود نص غير فارغ، ثم تحقق ذلك يدويًا |

## حدود صادقة

لا تمنع الواجهة تصوير الشاشة أو نسخ النص بعد عرضه، ولا تجعل النظام تشفيرًا طرفيًا بين المرسل والمستلم. الخادم موثوق ويرى النص لحظيًا ليشفّره ويفكّه، بينما تحتفظ قاعدة البيانات بالبيانات المشفّرة فقط. فتح الرابط الصحيح يستهلكه مباشرة؛ لذلك ينبغي إرسال الرابط فقط لمن يقصد المرسل أن يقرأ الرسالة.

## حالة المرحلة

اكتملت إعادة التصميم والفحوص المحلية. لم يُنشر المشروع علنًا في هذه المرحلة؛ يلزم إجراء النشر من واجهة المشروع بعد إنشاء نقطة استعادة، ثم فحص الرابط الدائم في بيئة الإنتاج.
